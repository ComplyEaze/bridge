- A voucher window read that is too large for one call is now refused within its first count requests when its vouchers are recent, instead of after counting the whole book (#2372). The count of a window now walks the company's vouchers from the newest change down. `voucher_window_too_many_reads` also carries `reads.certainly_refused`: the shortest run of days whose vouchers alone are more than one call may read, so any window that contains it is refused again. It also gives a next step: a narrower window (on a book of about a million vouchers, one day per call), or `trial_balance` for a period's totals. A window outside that run is not promised to fit.
