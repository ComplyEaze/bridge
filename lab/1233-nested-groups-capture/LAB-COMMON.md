# LAB-COMMON v3: rules that every Windows lab item of this set carries (626-T, 1038-R, 1050-D; 13 Oct 2026). An item names its company "THE COMPANY" with its number and GUID; this text applies to it in full. Where an item and this text differ, the stricter one holds. The lab's standing rules stand above both. Do not start an item without this text in front of you.

C1. THE COMPANY ONLY. START: no company loaded is what the lab is left with; load THE COMPANY by Select Company, then step 0. If another company is loaded at the start: STOP; shut nothing. Whenever anything is sent or keyed, THE COMPANY is loaded and no other is (during a restore none is loaded). Nothing is sent, keyed, backed up or restored while any other company is loaded. Synthetic companies only. Tally showing Educational mode anywhere (title bar or Gateway) = STOP.

C2. STEP 0 (before the item's first step, again after any pause, and wherever the item says). It BEGINS with a screenshot of the whole Tally window: a dialog, a message box or a half-entered screen = STOP before anything is sent, GET /status included. Then four observations, each kept as a file:
  a. From cmd.exe, with 2>&1 and the exit code recorded: `tasklist /FI "IMAGENAME eq tally.exe" /FO CSV /NH`. EXPECT exactly one line naming tally.exe; record its PID.
  b. From cmd.exe, likewise: `netstat -ano`. EXPECT at least one TCP line in state LISTENING whose local address (second column) ends in :9001, each carrying that PID; the file also holds a LISTENING line for another port (if not, the command failed).
  c. `curl.exe` GET /status on port 9001: curl exit 0, status 200; record the bytes.
  d. THE COMPANY is the only one loaded: a screenshot of the Gateway of Tally showing it as the one company, and a MARKS read sent now holding exactly one COMPANY row, with its GUID.
  A substitute for a or b is a read-only listing command only (nothing that ends a process); record each command and its exit code. A command that fails, exits non-zero or prints an error is "the command failed", never "none found". Record also the date the Gateway shows as Tally's current date. Any miss = STOP: report and start nothing. Never "open application" on Tally; click the existing window. NOTHING in an item ends a process, by name or by number: no taskkill, no Stop-Process, no End Task.

C3. RAW REQUESTS, reads and imports alike, ONE at a time, each sent exactly so (the line the 12 Oct runs used; PowerShell's `curl` is another command): `curl.exe -sS -w "%{http_code} %{size_download}" --data-binary "@<file>" -H "Content-Type: text/xml; charset=utf-16" -D <headers file> http://127.0.0.1:9001 -o <answer file>`. Record curl's exit code, the printed status and bytes, and CONTENT-LENGTH from the headers file. Check the request file's sha256 (Get-FileHash) before each send; a different size or hash = STOP, nothing is sent. A non-zero exit, a status other than 200, a size that differs from CONTENT-LENGTH, or an empty body = STOP, reported as "the request failed", never as "nothing found" or "no change". No client timeout (no --max-time). A request without an answer in 10 minutes, or that ended without one, is NEVER sent again: STOP, leave that curl running, report. The same holds for GET /status. EVERY READ HAS A SIZE BOUND: the one the item gives, else 2,000,000 bytes; an answer above its bound = STOP before it is used (keep the file, record its size). NOTHING is sent to port 9001 while a dialog or a half-entered screen is on Tally's screen: after every write, and after every send of a request the item calls a NEW SHAPE, take a screenshot of the whole Tally window BEFORE the next request; a dialog there = C7, and nothing further is sent. A file that WRITES (an import) is sent ONCE in the item's life, whatever happened to the first send: it is never sent again, whether or not a later read shows its effect; if a read does not show it, STOP and report (a new send needs new files and a new go-ahead). A write is sent only if the MARKS answer read just before it held exactly one COMPANY row, THE COMPANY's, and no key was pressed in Tally since that read.

C4. READING AN ANSWER. Decode it (UTF-16LE, with or without a BOM). Before parsing drop ONLY the characters XML forbids, raw or as references: 0 to 8, 11, 12, 14 to 31; KEEP 9, 10 and 13 (a name may end in a line break, which arrives as the references 13 and 10). Parse it as XML; never a text search on the bytes. An answer that does not parse = STOP. ROWS are the COMPANY, LEDGER or VOUCHER elements that are children of ENVELOPE/BODY/DATA/COLLECTION; the CMPINFO block above holds bare count lines with the same tag names, which are not rows and whose figures are not counts of anything read. NAMES (NAME, LEDGERNAME, PARTYLEDGERNAME, NARRATION) are never trimmed and are printed so that a trailing line break shows (as \r\n) with their length in characters; numbers and dates are trimmed.
  - MARKS answer: one COMPANY row per company loaded. Record ALTVCHID and ALTMSTID, trimmed, from the row with THE COMPANY's GUID; no such row, or a second row = STOP.
  - Voucher answer: one line per VOUCHER row: DATE, VOUCHERTYPENAME, VOUCHERNUMBER, MASTERID, ALTERID, GUID, NARRATION, then each ledger entry as LEDGERNAME, AMOUNT, ISDEEMEDPOSITIVE; sorted by MASTERID as a number. Count them. Every GUID begins with THE COMPANY's GUID, else STOP. Keep each table as a file.
  - Import answer: every counter must be present. EXPECT CREATED equal to the number of objects in the file and ALTERED, DELETED, COMBINED, IGNORED, ERRORS, CANCELLED and EXCEPTIONS all 0, with no LINEERROR, unless the item's step says otherwise. RECORD LASTVCHID and LASTMID. Anything else = STOP. The counters are never the proof: the read after it is.

C5. BACKUP, taken BEFORE the item's first change to the book, by Tally's own Backup screen with THE COMPANY loaded, to a NEW EMPTY LOCAL folder the item names (a directory listing BEFORE shows it absent or empty, else STOP; a listing AFTER shows the one backup file). The screen's "Backup Data Path" opens on cloud storage: change it to "Specify Path" and the local folder BEFORE accepting; select THE COMPANY only; screenshot the screen (the path exactly as the item names it, one company) BEFORE accepting. Record the local time of the backup to the minute (the Restore list shows it). CONFIRM before anything else: the file is in that folder (Tally names it TDBK1800_<company number>.001), it is above 0 bytes, and its name, folder, bytes and sha256 are in the notes. Missing, 0 bytes, no hash, or a file in cloud storage = STOP, and report the path the screen showed. A message that only says the backup is done: screenshot, accept once. A prompt to overwrite or replace a file: no key, STOP (a backup is never overwritten). Then one MARKS read. After a backup, record both marks; a difference is a result to record, not a STOP.

C6. RESTORE, made by the operator on Tally's screen, never by a request. THE SOURCE IS IDENTIFIED by all of: its folder, its file name, its bytes and sha256 as recorded, and the date and time the Restore list shows for it; any one differing = STOP. Before each: check the backup file's sha256 against the one recorded and that its folder holds that one file only; write restore-plan.txt (folder, file, hash, company number, Restore Data Path, the two prompts expected); keep a directory listing (names, sizes, times) of THE COMPANY's own data folder (the folder named by its number under the Restore Data Path) before the restore and again after it. Shut THE COMPANY first. Restore (under Data, Backup & Restore): Restore Data Path = Tally's data folder; source = "Specify Path", the backup's folder; the list must show THE COMPANY with its number and the date and time of the backup meant; select it ONLY; screenshot before accepting. Two prompts are expected and are the only ones answered: "Accept ?" = Yes; "Company data folder (<number>) already exists (the number must be THE COMPANY's). Selecting Skip will cancel the Restore process for this company. Selecting Replace will overwrite the existing folder." = Replace. Any other prompt, an offer to repair, rewrite or migrate, or a list that differs from the plan = press no key, screenshot, STOP. The Replace prompt NOT appearing, a restore that is not back at the menu in 10 minutes, or THE COMPANY missing from Select Company or not opening afterwards = press no key, screenshot, send nothing, STOP and report "the restore of <backup> did not complete". Otherwise load THE COMPANY alone. BEFORE any request after a restore: a screenshot of the whole Tally window (no dialog, no half-entered screen) and one of the Gateway showing THE COMPANY as the one company. Then the reads the step names, MARKS first. The item says what the book must hold after each restore; if it does not: STOP, and the way back is the backup the item names as its fallback, restored only on the run coordinator's word.

C7. SCREENS AND DIALOGS. On a master or voucher-type screen NEVER press Escape (on the lab it blanked a field): leave such a screen with Ctrl+Q, only after a screenshot shows that screen's title, and never press Ctrl+Q at the Gateway. The only prompts answered are a screen's own accept (a voucher, a master, the Backup and Restore screens), the prompts C5 and C6 quote, and any the item's step names. Any other dialog in Tally, at any step: screenshot it, copy its text exactly, press NO key, send NO request while it is up, report at once. It stays on the screen until the run coordinator answers.

C8. AFTER A STOP: nothing further is sent, keyed, backed up or restored. The STATE READS (MARKS and the reads the item ends each step with) may each be sent ONCE more to record the state, and only if no dialog is up, the Gateway shows THE COMPANY loaded, GET /status answers and the STOP was not itself a request, read or write, that failed or did not answer. A STOP that leaves a write or a restore in the book says so in its report, in the item's own words for that step (each item lists what the book holds after each step). If the run coordinator's word is to end the item there, the route back is: any restore it orders (C6), then C10, so that the lab is again one Tally with no company loaded. A backup is restored after a STOP only on the run coordinator's word.

C9. IF TALLY HANGS: STOP and report; nothing is re-opened or ended. IF TALLY HAS CLOSED (tasklist shows NO tally.exe): the operator itself opens Tally once, shuts any company that loaded by itself, loads THE COMPANY alone, runs step 0, then the STATE READS once each; then it STOPS and reports before any further step. An item is resumed only on the run coordinator's word, from the first step not done, after state reads that equal the last ones kept; a write once sent is never sent again, and a screen act the reads show as done is not repeated.

C10. CLOSE (every item's last step; the lab is left as it was found): shut THE COMPANY by Tally's own Shut Company (write down the menu path and key used). C2 a and b again (one tally.exe owning 9001); GET /status 200; a screenshot showing NO company loaded, with Tally's current date as recorded at step 0 (an item that changed it sets it back before the shut). No XML request is sent after the shut. If any of these is not so: do nothing further and report exactly what is on the screen.

C11. EVIDENCE. Every answer in full with its size and sha256 (an item may say that some answers stay on the lab PC, listed by hash), every table, screenshots (NEVER pushed: they stay on the lab PC, listed by name, size and sha256), restore-plan.txt, a notes file with UTC times and ONE line per step (the act; what was read; the marks before and after). GET /status before the first request and after the last. A result that differs from an EXPECT line goes to the run coordinator before the next step. The evidence branch is pushed only after the pre-push scan and the run coordinator's yes; notes name no roles and no people, carry no user names and no machine paths beyond the lab folders named in the item.
