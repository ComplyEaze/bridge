- A receipt log or Terms of Use record left with its last line cut short no longer stops ComplyEaze Bridge. Previously, when a process stopped part way through writing a line (for example, a host replacing the MCP server after giving a call up), every later receipt was refused and the session ended, until the file was edited by hand; the Terms record read as unavailable. Now the cut line is never read as a receipt or an acceptance. The next write repairs the file by appending, never by removing bytes: a `#` line and a `torn_record` marker giving the cut bytes' offset, length and sha256. `egress_log` lists those markers in `torn_records`, and gives the size of a cut line not yet repaired in `unrepaired_tail_bytes`. A line that is neither a whole record nor exactly vouched for by the marker after it is still refused, and so is a line that is not one JSON object (#2172).
