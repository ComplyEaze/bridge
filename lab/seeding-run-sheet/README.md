# Seeding: HSN on one stock item and one stock group, and the TDS, TCS and GST-classification settings, on BRIDGE SHAPE LAB

Synthetic company `BRIDGE SHAPE LAB` only, loaded alone, nobody else using this PC for Tally or this book from step 0 to step 17. **This sheet WRITES, on the screen and nowhere else:** an HSN/SAC code on ONE stock item and on ONE stock group, and three company settings (TDS, TCS, GST classifications). Nothing else is keyed, altered, accepted, created or deleted; no voucher screen is opened; no master is created; Tally's current date is never changed; never use Accept As Is. A backup is taken first (to a new empty local folder) and the book is restored from it at the end, with the first reads compared byte for byte. Nothing is sent over the gateway except reads (six requests, all Export); no company setting is changed over the gateway.

Why, and what this is evidence of. The read-only run found that no stock item and no stock group of this book holds an HSN code (0 of 11 items, 0 of 3 groups), and that TDS, TCS and GST classifications read No. This run captures, once, the wire shape of: one HSN entry keyed on Tally's own screen on one stock item and one stock group, and the company flags TDS and TCS turned on (GST classifications only if a field for it shows). It does NOT set any TDS or TCS details, nature of payment, deductee type or GST classification master, so it answers only the flag reads and the stock-master HSN read; the richer statutory reads need a different sheet. The values are test values on a synthetic book; the captures are evidence of the shape of values keyed on the screen, never of any real book's content. Each change is made alone and read back before the next, so each answer has one cause.

Files: `requests/` (6), `check.py`, `check-request-ids.py`, `SHA256.txt`. Check the files against `SHA256.txt` first (PowerShell: `Get-FileHash -Algorithm SHA256 FILE`), then run `python -I check-request-ids.py requests` (or `py -3 -I ...`). EXPECT exit 0 and `census: ok 5, skipped 1, FAIL 0` (the one skipped file is the whole-company object read, which names no collection).

**Exit codes of `check.py`** (its output is ASCII only; run it as `python -I check.py ...`): 0 = PASS; 1 = FINDING (an EXPECT did not hold: keep the file, write the line down, go on unless the step says STOP); 3 = STOP; 2 = the check could not run (never a pass; tell us). Every command below is written in full; nothing is to be assembled by the operator. `py -3 -I check.py ...` is the same command.

**General STOP rule.** Stop and tell us before going on if: Tally shows any dialog, message or warning that the step does not name; `check.py` exits 3 or 2; an answer is not a complete envelope, carries a `LINEERROR` or has header `STATUS` 0; an answer is above its cap; an answer has not finished after five minutes (do nothing at all: do not cancel it, do not send it again, do not send anything else, do not touch Tally; tell us and wait); `GET /status` after a request is not HTTP 200 `TallyPrime Server is Running`; a screen offers a field this list does not name and requires it. Never type a TAN, a registration number or any identifier of your own. Never press Escape on a screen with unsaved entries: save, or STOP and tell us. Leaving a screen: only when a screenshot shows that screen's own title, and after its save, use Ctrl+Q once; never press Ctrl+Q at the Gateway (it offers to quit Tally); if a save returns you to the Gateway, press nothing there; any prompt on leaving means press no key and STOP.

**Named prompts, not stops.** `Accept ?` (Yes) at the Backup screen, at the Restore screen, and when a master or the company screen is saved; at the company screen it may also appear once after a details form below, where the answer is No (stay on the screen) until every feature of that screen is set; the forms `Company TDS Deductor Details` and `Company TCS Collector Details` opened by steps 10 and below; the Gateway line `* (e) Data exceptions exist` (seen on this book in the read-only run; it is a line at the Gateway, take no action on it). Any other prompt: STOP.

**A STOP after step 8 leaves the book seeded.** From step 8 on the book differs from the read-only run's book (HSN codes, TDS/TCS on). After a STOP there: change nothing more, do not restore, and tell us; the restore is done only on our word. Until the restore is done and step 15 passes, no other sheet may read `BRIDGE SHAPE LAB`: whatever it showed would be captured as the book's own state. A STOP before step 8 leaves the book as it was (the backup folder may exist; tell us).

**How to send.** One request at a time: `curl.exe -s -S -X POST -H "Content-Type: text/xml; charset=utf-16" --data-binary "@requests\FILE" -o ans-NAME.xml -w "%{http_code} %{size_download}" http://127.0.0.1:9001`, each answer written with `-o`, never piped, no client time limit (an abandoned request can leave the gateway stuck). Note curl's exit code and printed line for every request, then `curl.exe -s -S -o status-NAME.txt -w "%{http_code}" http://127.0.0.1:9001/status`.

**Loading and shutting a company.** Use only Tally's Select Company screen: pick the company from its list and press Enter to load it; to shut a loaded company use the shut action on that same screen. If more than one company is loaded, or the screen offers any choice this list does not name, STOP.

**Codes used.** Item `Soda Ash Light` (the one item whose answer shows GST detail content, parent `Raw Chemicals`): HSN `28362010`. Group `Raw Chemicals`: HSN `2836`. Each applicable from 1-Apr-2025 (the book's first day, also the date of the item's existing GST rate row). They are test values on a synthetic book.

**Sizes.** Caps rest on the earlier answers of the same request on this book: `s05` 21,606 B (cap 40,000), `s06` 6,730 B (cap 20,000), the company features 5,822 B (cap 8,000), the book extent 3,838 B (cap 6,000). The whole-company object read has no earlier answer on this book: it is a NEW SIZE here, capped at 130,000 B (another book answered 84,634 to 86,692 B with the same request, in under a second) and a STOP above.
