# 2018 alternate units (#2018, #2017): what the quantity text of Stock Query and of the stock items collection looks like for an item that has an alternate unit

About 1 hour. This sheet WRITES: one company setting (the inventory feature that offers alternate units) is changed, two stock items are created by hand, they are read, and the book is restored from a backup; ComplyEaze Bridge only reads. Not for merge. `SHA256.txt` lists every file here with its bytes; check it before step 0.

## What it decides
`lab/2018-stock-query-names-units-dates-answers` could not set an alternate unit: the Stock Item Creation screen went from Units straight to Maintain in batches, with no Alternate units field, so the quantity text of an item with an alternate unit is not measured. Every quantity text read so far is one number and one unit (`150.000 Kgs`, `25 Nos`, `100 Box`). A planned read-only `stock_by_batch` tool (#2018) parses that text as an exact number and a unit equal to the item's base unit, and refuses any other shape; it also cannot tell from the collection (no element signals an alternate unit) which items have one. This sheet turns the alternate-unit feature on, creates two items that have one (`Alt Unit Probe A`, opened with 30 Nos, and `Alt Unit Probe B`, opened as 3 Box, on a conversion of 1 Box = 12 Nos), and records how Stock Query and the stock items collection write their quantities and units, and whether turning the feature on changes any answer for the existing items. It decides no tool, field or estimate.
