# 2089 statements on the two closing-stock books (#2089, Part of #2068): what `profit_and_loss` and `balance_sheet` answer when the ledger collection holds a Closing Stock row that does not add up, read only, on both books

Not for merge. About 1 hour 15 minutes. Read only: no key is pressed in Tally except to load, view and shut a company, nothing is created, altered, imported or restored, and no backup is needed (C5 and C6 do not apply: neither book changes). `SHA256.txt` lists every file here with its bytes; check it before step 0.

## What it decides
`lab/2068-nonint-trial-balance-answers` and `lab/2068-integrated-write-control-answers` found, on two synthetic books, that a Closing Stock ledger under Stock-in-Hand whose closing balance was keyed on Tally's screen keeps its opening as `TBALCLOSING` (-1,000.00) and shows the keyed change only as `DEBITTOTALS` (-400.00): its row does not add up (opening + debit + credit is not the closing). #2089 reads from the code that `profit_and_loss` and `balance_sheet` refuse a Trial Balance holding such a row: error code `profit_and_loss_read_failed` or `balance_sheet_read_failed`, cause `statement_trial_balance_row_inconsistent`, no remediation, nothing naming the ledger. That check runs on every row before anything else is derived, so the other refusal the statements know for a Stock-in-Hand ledger that carries an amount (state `not_established`, reason `closing_stock_not_derivable_from_trial_balance`) cannot appear on these books. Nobody has run the statements on these two books. This sheet records, for each book, on the same dates, with the same tool build: the raw ledger collection kept whole (so a fixture can be taken from Tally's own bytes), what `trial_balance` returns for the ledger, and the whole answer of `profit_and_loss` and of `balance_sheet`. EXPECT the row refusal on both tools and both books; any other answer (including an answer that names the ledger or carries figures) is the finding and is recorded whole. It decides no change to the tool.
