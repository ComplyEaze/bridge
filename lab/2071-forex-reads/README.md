# Lab run sheet: the three foreign-currency reads on the 0.7.0 build, before and after adding purchases, payments, a part receipt and a rupee control party (#2071). SYNTHETIC COMPANY ONLY. Not for merge.

About 90 minutes: two backups, three ledger masters and seven vouchers keyed on screen, two rounds of three tool reads, two rounds of six raw reads. ComplyEaze Bridge writes nothing.

**WHY:** on BRIDGE FOREXGROUP LAB the two sittings of `lab/2071-forex-rerun` (answers on `lab/2071-forex-rerun-answers` and `lab/2071-forex-repeat-answers`) found three refusals. Two of them are now handled in code: the Trial Balance and the compliance ledger read set aside a ledger whose balance is in TallyPrime 7.2's foreign-currency layout (#2141), and the compliance refusal gives a next step (#2124). Neither has been read through the built tools since. The third, `outstandings`, still refuses on the payable report's row for a USD bill whose closing amount Tally sent empty. Only one such row has been seen: a sales bill, settled in full at a different rate. A fix must know which other rows Tally sends that way, and whether a rupee party's bills keep arriving as plain amounts beside them.

**WHAT IT DECIDES:**
1. Whether the 0.7.0 build's `trial_balance` and `ledger_masters` (compliance) answer on this book, and which ledgers they set aside (round A, the book as the earlier sittings left it).
2. 3. The same three tool answers in round B, so the code change can be tested on Tally's own bytes.
