# Lab run sheet: item quantities inside nested stock groups against Tally's own Stock Summary (#1233). SYNTHETIC COMPANY ONLY. Not for merge.

About 75 minutes. `LAB-COMMON.md` in this folder (v3, a byte copy from `lab/2015-goods-lines-notes`, sha256 `5370c6d288cd0f54a4ac547c513ec1648dd8bec0ea5a327d46b0de519a6369c6`) applies in full; where this sheet and it differ, the stricter holds. A new company is created and its masters are keyed on Tally's screen; ComplyEaze Bridge writes nothing. Nothing is restored: the book stays on the lab PC as a parked lab book.

**WHAT IT DECIDES.** `stock_summary` reads every item's closing quantity from the stock item collection (`Bridge Audit Stock Items`) and returns it only where Tally's plain Stock Summary report shows the same item on its own line. In the captures so far that report has a line only for what sits directly under Primary, so an item inside a stock group gets `closing.quantity.state` `inside_stock_group` and no amount (`native_stock_summary.rs`, `agreement_of`), and a book with nested groups gets no quantities at all (protocol reference, measurements part, §12a.13). The proposed change returns a nested item's quantity from the collection, marked as not checked against Tally's report, and never as `agreed`. It ships only if this capture shows, on a book with groups three deep, that the collection lists every item at every depth and that each nested item's quantity and unit equal what Tally's own Stock Summary shows when every level is expanded. Any one that differs, or an item the collection leaves out, and the change is not made.

The built tool withholds the quantity this sheet must compare, so the collection's answer is captured as well, by curl, from the product's own request (below). `stock_summary` and `masters` are still called, to record what the product returns today on such a book.
