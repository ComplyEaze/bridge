# Lab run sheet: does changing a ledger's GST duty head move the company's master mark? (#1423, capture 1). SYNTHETIC COMPANY ONLY. Not for merge.

About 40 minutes. `LAB-COMMON.md` in this folder (v3, a byte copy from `lab/2015-goods-lines-notes`, sha256 `5370c6d288cd0f54a4ac547c513ec1648dd8bec0ea5a327d46b0de519a6369c6`) applies in full; where this sheet and it differ, the stricter holds. One ledger is created and altered on Tally's screen and removed by a restore at the end; ComplyEaze Bridge writes nothing and no raw request is sent.

**WHAT IT DECIDES.** `purchase_register` and the other register reads take the ledger masters before the voucher window and again after it, and refuse when the second read classifies differently from the first (`ledger_snapshot_drifted`), "because whether a duty-head change, a re-parent or a delete moves the master mark is unmeasured" (docs/agent/README.md, snapshot binding). A re-parent (regroup) and a ledger delete made on Tally's screen have since been measured to move `ALTMSTID` by 1 (protocol reference, measurements part, §11c.5, one run each). The duty-head change is the one left. This row measures, on TallyPrime 7.2, whether changing a GST duty ledger's tax type, and separately its type of duty, moves the master mark, each change made twice. If every change moves it, the mark alone would catch a duty-head change between two reads; if any does not, the second masters read stays the only guard and the docs say so.

**THE COMPANY.** BRIDGE SHAPE LAB, GUID `3a6bd6e1-b835-4bff-89dd-8a6af138c346` (in the merge gate's synthetic registry), loaded alone; GST on; it already holds duty ledgers `CGST`, `IGST`, `State Tax` and `Cess` under Duties & Taxes (the 27 Oct 2026 tool read classified them `cgst`, `igst`, `state_tax`, `cess`). **PASS (the row ran)** = every call answered whole and kept, each change keyed as written (or its STOP recorded with the screen), the restore back to M0/V0/T0 with no probe. The finding is the five mark differences, whatever they are. **FAIL** = a call that failed recorded as a result, a change keyed other than as written, or a book not restored.

**THE FINDING** (recorded, with its confidence marker, in the protocol reference's measurements part beside §11c.5 by a later change): for each of D1 to D4, whether `ALTMSTID` moved and by how much, and whether the probe's duty head as `ledger_masters` reports it followed the screen. Two runs of each kind of change (D1/D2 tax type; D3/D4 type of duty). If every difference is at least 1, a duty-head change on Tally's screen moves the master mark (VERIFIED for a ledger with no vouchers, 7.2). If any is 0, it does not, and the second masters read stays the only guard.
