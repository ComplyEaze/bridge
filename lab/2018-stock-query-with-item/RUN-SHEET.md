## What it decides
`lab/2018-batch-report-routes-answers` tried the titles of the screens that show stock by batch as report IDs in the Stock Summary's own request shape. Every one was refused in band like the unknown-name control (STATUS 0, "Could not find Report"), except `Stock Query` (and its spaceless spelling `StockQuery`, byte-equal), which answered 200 with an empty envelope (46 bytes, `RESPSTATUS` 1, no STATUS and no line error). On Tally's screen the Stock Query of the item lists, under "Godown/Batch Details", the closing quantity per godown and batch (Main Location / Primary Batch 150, Main Location / H-2504-A 300, Factory Floor / H-2504-B 366.667): exactly the data #2018 and #2017 want. The empty answer may mean the report needs a stock item chosen. This sheet sends `Stock Query` again with the item named by one static variable, from a closed pair of candidate names (`STOCKITEMNAME`, `SVSTOCKITEM`: unverified guesses), each once, beside a third variable name that Tally does not have (the control for whether any extra variable changes the answer), a second control that names an item the book does not hold (a refusal that names the variable would show Tally knows it even if the report stays empty), and the Stock Summary and unknown-name controls. The repo holds no evidence for any item-scoping variable name: `STOCKITEMNAME` is the field name an inventory entry carries and `SVSTOCKITEM` follows the SV prefix of Tally's system variables, both guesses. An extra static variable on a measured report stayed in band (`EXPLODEFLAG` on the Stock Summary), and a bad variable value was refused in band. An answer with lines is the finding; an empty or refused answer for both candidates is also a result. It decides no read, tool name or estimate for #2018.
