# LAB-COMMON-RA: the rules row 1381-RA carries (written for this row, 26 Nov 2026)

This row sends ten reads by file to the lab's Tally, with one synthetic book loaded, in Educational Mode. LAB-COMMON v3 (blob c4badf8c, the text row 1381-R1 carried) makes Educational Mode a STOP in its C1, which on today's lab stops every row; its C5 and C6 (backup and restore) are not acts of this row. These clauses take its place for this row only. Each says which v3 clause it keeps, changes or drops. Where the run sheet and this text differ, the stricter holds. The lab's standing rules stand above both. Do not start the row without this text in front of you.

R1. THE BOOK ONLY (v3 C1, changed). The book is `BRIDGE STOCK CREATE LAB`, synthetic, with no other company loaded at any send. At the start no company is loaded; the book is loaded by Tally's own Select Company screen, as rows 1381-O and 1381-R1 loaded it. Another company loaded at the start: STOP-OTHER-COMPANY, shut nothing. The book absent from Select Company: STOP-BOOK-ABSENT. The book's state is checked by M1 before any other read (`measure.py state`): anything but one company row, the book's GUID, ALTMSTID 210 and no ALTVCHID is STOP-BOOK-STATE. A restore is not part of this row (R5).

R2. THE EDITION (v3 C1's last sentence, replaced). The lab's Tally runs in Educational Mode: its title band reads `TallyPrime EDU` (lab 2162-PA, 25 Nov 2026: the Silver Rental licence lapsed on 24-Nov-2026). That is the state this row measures, not a STOP. A title band that does not read `EDU` at step 0, or that changes at any later screenshot, is STOP-EDITION: nothing further is sent, and the row waits for the run coordinator's word (one variable at a time: the row is not run half in one edition and half in another).

R3. STEP 0 (v3 C2, kept, with one change). It begins with a screenshot of the whole Tally window: a dialog, a message box or a half-entered screen is STOP-DIALOG before anything is sent. Then, each kept as a file with its exit code: (a) `tasklist` for `tally.exe`, exactly one line, its PID recorded; (b) `netstat -ano`, a LISTENING line on `:9001` with that PID and a LISTENING line for another port (else the command failed); (c) GET `/status` on 9001, curl exit 0 and status 200, its bytes recorded; (d) no `bridge_mcp.exe` running (a running one could send to 9001 during the sitting: STOP-STRAY). Then the load (R1), a screenshot of the Gateway showing the book as the one company, and Tally's current date as the Gateway shows it. The change: v3 C2 d's MARKS read is M1 itself, sent by `send.py`, and is the first of the row's ten reads. Any miss: STOP, as the sheet names it. Never "open application" on Tally; click the existing window.

R4. THE TEN READS (v3 C3, changed). Only `send.py` sends, and only the ten reads it names, in its fixed order M1, C1, C2, I1, I2, G1, G2, U1, U2, M2, one at a time, each once in the row's life whatever happened to it, to `http://127.0.0.1:9001` only, by v3 C3's curl line with no client timeout. `send.py` checks each request's sha256 and size against `SHA256.txt` before it sends. Nothing else is sent to Tally between M1 and M2: no GET `/status`, no other file, no key or click in Tally's window. A non-zero curl exit, a status other than 200, a missing or different CONTENT-LENGTH, an empty answer, or an answer above 2,000,000 bytes is STOP-REQUEST-FAILED, recorded as "the request failed", never as "nothing found"; `send.py` then refuses every later send. A request without an answer in 10 minutes is STOP-NO-ANSWER: that curl is left running and nothing is sent again. After C1, the one request no earlier row sent to this book (v3 C3's NEW SHAPE), a screenshot of the whole Tally window is taken before C2: a dialog there is STOP-DIALOG.

R5. NO WRITE, NO BACKUP, NO RESTORE (v3 C5 and C6, dropped). Nothing in this row writes to the book: every request is one Export of a Collection, with no import (`gen_ra.py` and `check_sheet.py` check). No backup is taken and no restore is made. If the book is absent or its state differs (R1), the way back is one of the two backups the sheet's The book names (row 1108-R3's BK-S, the latest, and row 1381-O's backup-1, both taken at ALTMSTID 210 with no voucher), restored by v3 C6 as a separate act, only on the run coordinator's word, and never inside this row. No restore has been made in Educational Mode on this lab.

R6. READING AN ANSWER (v3 C4, kept). `measure.py` reads as v3 C4 says: UTF-16LE with or without a byte-order mark; only the characters XML forbids dropped, raw or as references, keeping 9, 10 and 13; parsed as XML, never a text search on the bytes; rows only as children of `ENVELOPE/BODY/DATA/COLLECTION` (the CMPINFO block's bare count lines are not rows). An answer whose send failed, that is empty, that does not parse, or that is not a success envelope is `NOT READ`, never zero rows.

R7. SCREENS AND DIALOGS (v3 C7, changed). The only keys and clicks in Tally are those of the load (Select Company), the screenshots, and the close (Shut Company). At a Shut Company, and only there, a pair of screens may follow (lab 2162-PA, 25 Nov 2026, once in two shuts): a dialog asking whether to visit Tally's website to renew the licence, answered **No by click** after a zoom shows its two buttons, never by Enter; then a screen titled License, answered **"T: Continue In Educational Mode" by click** after a zoom. Never Yes, never P (Update Existing License), never U (Use License From Network), never "Manage Rental License", and no renewal, licence or activation screen is opened. Any other licence dialog or screen, or this pair anywhere but after a Shut Company, or anything after T but Select Company, is STOP-LICENCE: press no key, copy its text, report. Any other dialog in Tally at any step: screenshot it, copy its text exactly, press no key, send nothing, STOP-DIALOG.

R8. NOTHING ENDS A PROCESS (v3 C2's last sentence, kept). No `taskkill`, no `Stop-Process`, no End Task, by name or by number. A curl left waiting stays; Tally stays.

R9. IF TALLY STOPS ANSWERING OR CLOSES (v3 C9, changed). If Tally stops answering, or `tasklist` shows no `tally.exe`: STOP-TALLY, report; nothing is re-opened or ended, and the row does not resume in this sitting (its pairs and its M1 to M2 bracket would no longer be one sitting). A new sitting needs new answers and a new `local/` folder, on the run coordinator's word.

R10. AFTER A STOP (v3 C8, changed). A STOP leaves things as they stand: nothing further is sent, no file is moved or deleted, no process is ended. Report it with its name and the files that show it to the run coordinator before anything else. No read is sent again to record the state: in this row every read is sent once (R4). The close (R11) follows a STOP only on the run coordinator's word.

R11. CLOSE (v3 C10, kept). The book is shut by Tally's own Shut Company (the menu path and keys written down), with R7's pair answered if it comes. Then R3 a, b and c again (one `tally.exe` owning 9001, GET `/status` 200) and a screenshot showing Select Company with no company loaded. No XML request is sent after the shut. The lab is left as found.

R12. FILES (shape of row 1381-BX's B6). The row folder is `C:/bridge-lab/1381-ra`, copied whole from the sheet's commit. Everything the lab adds goes into `C:/bridge-lab/1381-ra/local/`; no file is overwritten (`send.py` refuses a name already used, and every send line refuses a record that exists), except inside `local/selftest/`, the self-tests' own scratch folder, which they write afresh at each run. A check line writes its own record with `>` and is typed once; a record is never rewritten by hand. The self-tests write only under `local/selftest/`, and `send.py` and `measure.py` refuse any other scratch folder inside the row folder. `check_sheet.py` skips `local/` and nothing else, so any other file outside `SHA256.txt` stops it; `check_sheet.py --fresh` at step 0 stops if `local/` holds anything step 0 did not make.

R13. EVIDENCE (v3 C11, changed). Every helper output whole, with its exit code, under `local/evidence/`; every answer under `local/answers/` exactly as received, with its headers and transport record apart from it. The answers of M1, M2, I1, I2, G1, G2, U1 and U2 carry only the book's GUID, which master lists as synthetic, and may be pushed whole. The answers of C1 and C2 carry the book's company number (`COMPANYNUMBER`): they stay on the lab PC, listed by name, size and sha256, unless the run coordinator says otherwise; `measure.py` never prints that number, so its output may be pushed. Screenshots, `netstat` and `tasklist` output stay on the lab PC, listed by name, size and sha256. A notes file with UTC times and one line per step. No real client data anywhere; notes name no roles and no people, and carry no user names and no machine paths beyond the lab folders named here. The evidence branch is pushed only after the pre-push scan and the run coordinator's yes.
