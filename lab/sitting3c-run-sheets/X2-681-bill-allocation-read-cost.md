# X2 (#681): what does the tax-audit voucher profile cost per voucher on a bill-wise book, beside the shipped read that carries bill allocations?
WHY: the tax-audit book model needs bill allocations, and a read that must fit a large book may need a named-field profile, which carries allocations only if it names them. The shipped wildcard read (ALLLEDGERENTRIES.*) already returns them at about 7.3 times a curated allocation fetch (protocol reference 8.2a). The tax-audit voucher profile (`ReadOnlyProfile::AuditVouchersV1`) is the baseline the issue names; it names fields and carries no allocation path. This row records the per-voucher wire bytes of both on a small bill-wise book and the content of the wildcard's allocations. It does NOT measure a named-field read with the allocation field added: that is a new request shape, and a new shape is measured through the dispatch path (deadline, size cap, window and census checks), not sent by hand; that measurement waits for a lab-only candidate builder in a separate change. P1: nothing about a format change is decided from this row alone.
RULES: LAB-COMMON v3 C1 to C11 apply in full. Check the file hashes against `requests-681/MANIFEST.txt` before the sitting; any difference = STOP. Send exactly as C3 says, one at a time, none twice. Licensed mode only; Educational mode anywhere = STOP.
