- After a tax-audit read is cut off, the next `audit_test_run` no longer stays refused as `audit_part_drain_required` until ComplyEaze Bridge is restarted. It meets the same check as every other request: `tally_endpoint_draining`, with `retry_after_s`, until Tally has finished, and then it runs. A response refused at its head now holds the next request the same way, because Tally may still be sending it (#2142).
