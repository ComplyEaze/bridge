# 2119 Bills report 60-second limit (#2119): `outstandings` at 31 March 2026 on the dense synthetic book through the build that gives the two Bills report requests 60 seconds, once by the lab's stdio client and once through Claude Desktop's chat, read only

Not for merge. About an hour. READS ONLY: nothing is created, altered, imported or restored, and no backup is needed (C5 and C6 do not apply: the book does not change). `SHA256.txt` lists every other file here with its bytes; check it before step 0.

## What it decides
The build under test sends Tally's Bills Receivable and Bills Payable report requests with a 60-second limit; every other request keeps 20 seconds. On BRIDGE CORPUS DENSE at 31 March 2026, the Receivable request alone took 41.5 s and 36.7 s by curl, and the tool on a 20-second build refused the call on that post (`lab/2119-bills-read-timing-answers`, R4, R5 and T3). The tool sends each report twice with `GET /status` between and after, so an answered call there is expected to take about 85 s.

The row decides, for this build:
1. **S1:** whether `outstandings` at 31 March 2026 answers through the lab's stdio client, with its totals equal to R4's, and how long each request was held.
2. **S2:** whether a read sent straight after it (`ledger_masters`) answers.
3. **P1:** what a second ComplyEaze Bridge process sees when it calls `tally_status` 10 s into S1.
4. **H1 and D1:** how long this Claude Desktop on Windows waits for one tool call, by the repository's sleep server with no Tally request (H1), and whether it waits for the whole `outstandings` call (D1). The repository's only measurement of a Desktop limit is on macOS (protocol reference §11f: silent calls up to 130 s answered, a 250 s call cut at 240 s; PARTIAL); the Windows row of `docs/agent/mcp-host-call-timeouts.md` is empty.

**The limit is held** (the release does not ship it as is; the run coordinator decides what follows) if any of these is so:
- **S1 is refused** with cause `native_bills_report_deadline_exceeded`: the coverage the limit was accepted on did not hold on this book.
- **S1 answers with totals that differ from R4's** (`open_bills_total` other than R4's `BILLFIXED`, or `receivable` other than the size of R4's `BILLCL` sum): a wrong answer is worse than a refusal.
- **Desktop gives D1 up.** An error whose text names a timeout or a cancellation is a give-up whatever its time. Any other error is a give-up only if Desktop showed it before the `response_prepared` record of that call in D1's `egress_log`; an error shown after it (for example about the answer's size) is recorded as a result.
- **Desktop's limit is not shown to be at least 90 seconds.** It is shown by H1's 130-second sleep call answering whole, or by D1 answering whole after Desktop waited at least 90 s for it. Otherwise the limit is held, with H1's and D1's times recorded.

It decides nothing about other books, other dates or Gold.
