# W2 (#1037): does a hand import through Tally's Import menu fill its own AlterID span in file order?
WHY: a native post is attributed by its position inside its own POST's AlterID span (protocol reference section 9.15). A file built for a person to import by hand still carries a narration tag because Bridge sees no marks around that import. Whether a hand import through the Import menu fills its own contiguous span, in file order, as the gateway import did, has never been measured; neither have the counters a UI import reports (there is no gateway response).

COMPANY: BRIDGE HANDIMPORT LAB (new, THE COMPANY), loaded alone: a bank ledger (Lab Bank), two party ledgers under Sundry Debtors, a Receipt voucher type with Automatic numbering and "retain existing numbers" on, no voucher on the chosen day D. If a company or data folder of this name exists on the PC, STOP and report it. Create it with books beginning 1 April 2025 (OWNER STEP); take backup BK1 into a NEW empty folder (name, size, sha256) before the first keying (C5).
MODE: B. Posting OFF: nothing is posted by Bridge in this row; the owner imports.
STEPS:
1. `list_companies`: expect exactly BRIDGE HANDIMPORT LAB, loaded alone; STOP before any call otherwise. GUID. `tally_status`: M0 (master mark), V0 (voucher mark). `vouchers` day D: N0 (expect 0).
2. `build_import_xml`: ONE saved batch of 3 Receipts on day D, each 1.00 from a party to Lab Bank, with distinct narrations "S1", "S2", "S3" in that order. PASS = consecutive AlterIDs in file order with no other voucher inside the span, and the screen's counters recorded verbatim.
