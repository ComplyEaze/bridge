At a glance, release 0.5.0

  • You can ask: outstanding receivables and payables, with ageing of the open bills; the trial balance for a period; the vouchers in a date range, found by number, reference, narration or amount and added up by ledger, month, voucher type, group or primary group (checked on one synthetic book, not a large one); Tally’s own Cash Flow for whole months, shown only when its net total ties to the trial balance (not a cash flow statement under AS 3; tried on two synthetic books); and one ledger’s opening, debits, credits and closing.
  • Partly, with limits: profit and loss and the balance sheet, which a book with stock items is expected to refuse (none has been tried yet) and a book with several currencies does refuse; closing stock value per item at 31 March, values only with no quantities, on small books only, and only the year to 31 March 2026 has been checked; and a password-protected SBI, HDFC or Union Bank of India PDF statement, read into a file of Payment, Receipt and Contra vouchers that you check and import in Tally yourself. It creates no ledger, it cannot build onto a Cash-in-Hand ledger, a line it cannot place goes to a suspense ledger you name, and it has not yet been run on a real bank statement.
  • Not in release 0.5.0: GST returns or GSTR-2B matching; making sales or purchase invoices or GST entries; tax-audit flags; Tally’s Funds Flow, Ratio Analysis and negative-balance reports.
  • “You can ask” means it answered on the books and builds we ran it on, which the README lists (not every read has its own recorded run); we have not yet run the published 0.5.0 file against TallyPrime. Very large books can fail or take longer than the assistant waits, and a book with several currencies is read only in part. Check any figure you rely on against Tally. Before you install

  • ComplyEaze Bridge is still being developed and may contain errors. Try it first on a test company, and take a backup before you turn posting on.
  • Posting is off by default in a new install. A ComplyEaze Bridge older than 0.4.2 left installed keeps its own settings, and one from before 0.3.0 may have posting on, so remove such a release first (see “Install, once” below). Release 0.4.2 installed as a new extension. A build of 0.5.0 made by our checks (not the published file), installed over 0.4.2 on one Mac, replaced it and kept its Tally port, Response redaction and posting setting (a posting setting that was on stayed on), so after you install it, tick the Terms of Use setting (version 2026-10.1) again and check the posting setting. There is no tool to undo or delete a posted voucher; you correct it in Tally. A post can still land in a company renamed after the last check, and a replaced ledger is not always noticed. The approval window for a post covers only ComplyEaze Bridge: another Tally connector in the same Claude Desktop that can change entries can do so without it. The README gives these limits in full.
  • Each download has a matching .sha256 file on the same release. Compare it with your download before opening the package.
  • Tally must be running on the same computer as Claude Desktop.
  • You bring TallyPrime and Claude Desktop, and what Claude reads goes to Anthropic. ComplyEaze Bridge has no account and no price set today.
  • On a Mac, run Tally in a Windows virtual machine on that same Mac with its gateway port forwarded to the Mac's localhost, or reach it through local port forwarding your organisation has approved. ComplyEaze Bridge talks to Tally only on localhost, so a separate PC, or a Tally elsewhere on your network, cannot be reached.

Install, once

  1. If ComplyEaze Bridge 0.4.2 is already installed, install the new file over it and keep its data folder, which both versions use. A build of 0.5.0 made by our checks (not the published file) replaced 0.4.2 on one Mac and kept its Tally port, Response redaction and posting setting. Installing over a release older than 0.4.2 was not tried: remove such a release first, keep its data folder, and enter your settings in the new one, including Response redaction, which starts at none. If Settings → Extensions lists two ComplyEaze Bridge entries (as happened when 0.4.2 was installed beside an older release), remove the older entry before you use either, enter your settings in the new one, including Response redaction, which starts at none, tick the Terms setting, and quit and reopen Claude Desktop (the steps below).
  2. In TallyPrime, turn on the HTTP gateway (Tally acts as “Both”).
  3. Open the downloaded .mcpb file. If Claude Desktop doesn’t pick it up: Settings → Extensions → Advanced settings → Install Extension. Claude Desktop may note that the extension is not verified by Anthropic.
  4. Check the Tally port in the extension settings (usually 9000).
  5. Read the Terms of Use linked in the extension settings, then turn on “I accept the ComplyEaze Bridge Terms of Use”. Until you do, ComplyEaze Bridge does not read from Tally, and from release 0.5.1 every tool answers that the Terms of Use are not accepted and names this setting. (In 0.5.0, after an update from 0.4.2, Claude Desktop did not start it before the box was ticked, and on one Mac a request failed with a 400 error that did not mention the Terms.)
  6. Save the settings, check that “Allow voucher posting” is as you want it, then quit Claude Desktop completely and reopen it. Then ask about your books in plain language.
