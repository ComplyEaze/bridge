- A refused `trial_balance` read now carries a `remediation`, and a `cause` when the Trial Balance answer could not be used (the rule it failed, such as `trial_balance_source_identity_missing` or `trial_balance_amount_invalid`), where it gave the code `trial_balance_read_failed` alone. `profit_and_loss`, `balance_sheet` and `cash_flow` show the same `cause`, and no other reason or step changes. The step is given to any refusal of this read that has none of its own, whatever its reason (a timeout, an HTTP error, an oversized answer or an unusable one): it tells the assistant to report what the cause says, or that the read failed when none is named, and not to repeat the same read in a loop. It does not say why a book with foreign-currency vouchers is refused: the cause is read from the refusal when the read is repeated on that book, and a failure after the answer was parsed still names none (part of #2071, part of #683).
