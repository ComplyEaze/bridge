# Missing reads: raw answers for allocations on vouchers, foreign currency, statutory masters and HSN

Synthetic companies `BRIDGE SHAPE LAB` and `BRIDGE CORPUS FOREX` only, one at a time. **Read only:** nothing is keyed, imported, altered, accepted or deleted, no company feature is changed, no backup is needed, and no voucher screen is opened. Tally's current date is never changed. Every request is a Collection export whose header `<ID>` equals the `NAME` of the collection the request defines, and every `<TYPE>` is one that an earlier committed request already sent (`Company`, `Currency`, `StockItem`, `StockGroup`, `TaxUnit`, `Voucher`).

The answers are the raw bytes a first slice of each read would be built from. Not sent again, because answers already exist: the HSN codes on ledgers, groups and the company of the synthetic book with company number 100033, its GST rate details, tax units and company object, the two foreign-currency vouchers of 15 September 2026, and the foreign-currency ledgers and trial balance (committed captures and lab branches). Not sent because they would need a seeding write, which is a separate sheet: TDS/TCS (the setting reads No on the three synthetic books read for it) and a GST classification master (also No on those three).

**What is new.** The raw answer of the cost-centre allocation voucher; the two-batch Purchase read twice (ledger entries, then inventory entries, a shape never sent before); HSN and GST detail lists on stock items and stock groups; tax units and the Currency master with every native method on books that have none captured. Where a step adds to a committed request, the table "Where each request comes from" names the source and the one change.

Files: `requests/` (14 requests, UTF-16LE with a byte-order mark), `check.py`, `check-request-ids.py`, `SHA256.txt`. First check the files against `SHA256.txt` (PowerShell: `Get-FileHash -Algorithm SHA256 FILE`; or `certutil -hashfile FILE SHA256`). Then run `python check-request-ids.py requests` (or `py -3 check-request-ids.py requests`; use `-I` after the program name where the launcher allows it). EXPECT exit 0 and the line `census: ok 14, skipped 0, FAIL 0`. Below, `check.py` is run the same way.

**Exit codes of `check.py`.** 0 = PASS: every EXPECT of the step held. 1 = FINDING: an EXPECT did not hold; keep the file, write the printed line down, go on. 3 = STOP. 2 = the check could not run (a missing file, a missing argument, any error): never read it as a pass or as a finding; tell us. Run it as `check.py STEP ANSWER [--census FILE] [--company FILE]`.

**General STOP rule.** Stop and tell us before going on if: Tally shows any dialog, message or warning this list does not name; `check.py` exits 3 or 2; an answer is not a complete envelope with a `COLLECTION`, carries a `LINEERROR`, or has header `STATUS` 0; any answer is above the cap of its step; an answer has not finished after five minutes (do not cancel it and do not send it again: wait, then tell us, and check that Tally still answers the book-extent request); `GET /status` after a request is not HTTP 200 `TallyPrime Server is Running`. Tally must be at the Gateway with no dialog open before every request. Never press Escape. Press nothing but what a step names.

**How to send.** One request at a time: `curl.exe -s -S -X POST -H "Content-Type: text/xml; charset=utf-16" --data-binary "@requests\FILE" -o ans-STEP.xml -w "%{http_code} %{size_download}" http://127.0.0.1:9001`, each answer written with `-o`, never piped, no client time limit. Note curl's exit code and printed line for every request, then `curl.exe -s -S -o status-STEP.txt -w "%{http_code}" http://127.0.0.1:9001/status`.

**Sizes.** Every cap comes from a named earlier answer of the same request on the same book, or the step says it is a NEW SHAPE or a SECOND BOOK and gives a cap and a STOP. (The earlier company-list and book-extent answers of the first book are trimmed to its own row: 6,140 and 5,652 bytes as received with three companies loaded, 4,000 and 3,838 as kept.) Voucher reads are sent only after the census of the same day has passed. A voucher answer may hold at most census count x 80,000 bytes and never more than 240,000: the largest committed one-voucher answer of this request is 76,868 B (a taxed sales day), the one-voucher answers of the first book are 65,002 B and 64,928 B (a debit-note day and a credit-note day), the whole-year read of that book had a first data part of 1,736,780 B for 42 voucher rows (about 41.4 KB a row), and the one foreign-currency voucher is 37,190 B.
