- A refused `trial_balance` read now carries a `cause` when the Trial Balance answer could not be used (the rule it failed, such as `trial_balance_source_identity_missing` or `trial_balance_amount_invalid`), where it gave the code `trial_balance_read_failed` alone. `profit_and_loss`, `balance_sheet` and `cash_flow` show the same `cause`, and no other reason or step changes. Every `trial_balance_read_failed` refusal that has no step of its own now carries one (a timeout, an HTTP error, an oversized answer or an unusable one): it tells the assistant to report what the cause says, or that the read failed when none is named, and not to repeat the same read in a loop. The refusals that have their own codes (before the books began, a period not honoured, Education mode, the base-currency codes) keep their own text and get no step from this. This does not say why a book with foreign-currency vouchers is refused: the code names the Trial Balance parser's reason when the answer could not be parsed, so the reason is read from the refusal when that read is repeated on that book. A failure in the totals after the parse still names no cause (part of #2071, part of #683).
