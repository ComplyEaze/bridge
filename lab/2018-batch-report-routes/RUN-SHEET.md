# 2018 batch-wise stock report, more routes (#2018): the titles of the screens that show stock by batch, each tried once as a report ID in the Stock Summary's own request shape, read only, on the synthetic book that holds godowns and batches

Not for merge. About 50 minutes. READS ONLY: nothing is created, altered, imported or restored, and no backup is needed (C5 and C6 do not apply: the book does not change). `SHA256.txt` lists every file here with its bytes; check it before step 0.

## What it decides
`lab/2017-2018-stock-by-godown-batch-answers` found that the godown report answers over the gateway under the ID `Godown Summary` (one closing line per godown), while the batch report, reached on Tally's screen as "Batch Summary" from Batch Vouchers with F8, is refused in band under `Batch Summary` and `BatchSummary` (STATUS 0, "Could not find Report", the same as an unknown-name control), and the screen shows no expiry column. #2018 (closing stock by batch, and expiry) still has no gateway answer. A screen's title is not always the gateway's ID (the screen "Profit & Loss A/c" is the ID "Profit and Loss"). This sheet records the titles of the other screens that show stock by batch (Batch Vouchers, the item's Stock Item Vouchers and Stock Query, and whatever batch-wise views their keys offer), and tries each title once, by the same three rules as before, as a report ID, with the same unknown-name control. (Expiry already has partial evidence: the first #2016 row read `EXPIRYPERIOD` inside `BATCHALLOCATIONS.LIST` through the inventory fetch, so the open question is a batch closing balance and a batch-master expiry.) A refusal for every title is a result; so is a title that answers with data. It decides no read, tool name or estimate for #2018.

Differences from LAB-COMMON, the stricter rule holding everywhere else:
1. **Two kinds of read.** Tool reads are calls of ComplyEaze Bridge's built tool, one at a time (`list_companies` and the marks only). Raw reads by curl are allowed by the owner's decision of 26 Oct 2026 for shape discovery: each is the committed Stock Summary report request (`templates/stock_summary_request.utf16le.xml`, the fixture `stock_summary_report_fy_request`) with only the report ID, the company and the dates changed, written by `make_report_request.py`, used as an instrument and sent once as C3 sets out. No other request is sent.
2. **No ID is guessed.** A candidate ID is derived only from the title Tally's own screen shows for a report, copied exactly (step 3), by these rules and no others: (1) the title as shown; (2) the title with `&` written `and` and every `/` dropped; (3) the title with its spaces removed. A candidate is sent only if it is plain (letters, digits, spaces, hyphens), once, in that order, and the first one that answers with data ends that title's list. A candidate identical to one already written for this title, or to an ID already sent in this row or by the 2017/2018 row (`Stock Summary`, `Bridge Probe Unknown`, `Godown Summary`, `Batch Summary`, `BatchSummary`), is not written or sent; record that. A title that cannot be a plain ID is not sent either (the script refuses it): record it and go on. At most six titles are tried. The control uses the name `Bridge Probe Unknown` (no such report exists). Every send is a NEW SHAPE: C3's screenshot of Tally's whole window is taken after each, before the next send. No static variable, item or batch is added to a request: a report that needs an item chosen and answers empty or refused is the result for that title.
3. **Marks.** `tally_status` carries no marks. M (`ALTMSTID`) and V (`ALTVCHID`) are read with `ledger_masters` with `fields` `compliance` (the basic read is refused on this book, cause `company_several_currency_masters`, as the 2017/2018 row recorded): `snapshot.master_alter_id`, `snapshot.voucher_alter_id`, `snapshot.reused` false. Marks are read before and after the group of raw reads, and must be equal.
4. **One Tally.** At step 0 and at the end, as C2 a and b set out (the process list and the listener on port 9001) plus `Get-NetTCPConnection -LocalPort 9001 -State Listen`: exactly one `tally.exe`, and it owns port 9001. A screen-control tool brings no window forward.
5. **Keys.** The screens opened are reports, their menus and the Gateway only. In a menu use arrows, Enter and Escape only (letters typed at the Gateway act as menu keys). In a report use arrows, Enter on an item, batch or month line to open its drill-down (never Enter on a voucher line: a voucher opens an alteration screen, which is left only by ONE Ctrl+Q after a screenshot shows its title, never Escape, C7), F2 to set the report's period, F8 or any side-bar key whose label names a batch-, godown- or item-wise view, and Change View (the side bar's H key) with, in its list, arrows, Enter and Escape only (Show More allowed), each recorded and followed by a screenshot. Never F3, F11, F12, Ctrl+B, Alt+C, Alt+N, Ctrl+E, Alt+E, Alt+P or Alt+M; a key not listed is not pressed. Leave a report with one Escape per level after a screenshot shows its title (C7 allows Escape on reports); **never Ctrl+Q or Escape at the Gateway of Tally**. No entry or alteration screen is opened on purpose.
6. **A modal dialog** at any step (an "Error in TDL" message above all): screenshot it, copy its text exactly, press NO key, send NO request, and report (C7). It stays on the screen until the run coordinator answers; the gateway is blocked meanwhile. A 0-byte 200 answer, an empty envelope and an in-band refusal (STATUS 0 with a line error) are **results** for these sends, not STOPs: C3's "empty body" STOP, and C4's "does not parse" STOP for a 0-byte body only, are set aside for them and nothing else. Any other outcome (curl exit non-zero, a status other than 200, a size other than CONTENT-LENGTH, no answer in 10 minutes) is C3 and C7: STOP. If a send has no answer after 60 seconds, take a screenshot of Tally's whole window without pressing a key; a dialog there is this rule (STOP). Whatever it shows, C3's 10-minute rule still applies to that curl.
