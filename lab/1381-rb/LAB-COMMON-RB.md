# LAB-COMMON-RB: the rules row 1381-RB carries (written for this row, 26 Nov 2026)

This row binds the one synthetic book at BK-S's state, sends one write by file in Educational Mode, reads what it changed, restores BK-S by Tally's own Restore and reads the book again. It keeps row 1381-RR's rules (`LAB-COMMON-RR.md`, lab/1381-rr-sheet at 62858add, R1 to R13) where they apply, and brings in LAB-COMMON v3 (blob c4badf8c) C3 to C5 for the write, which RR did not make. Each clause says which RR clause, or which v3 clause, it keeps or changes. Where the run sheet and this text differ, the stricter holds. The lab's standing rules stand above both. Do not start the row without this text and v3 C3 to C6 in front of you.

R1. THE BOOK ONLY (RR R1, changed). The book is `BRIDGE STOCK CREATE LAB`, synthetic, with no other company loaded at any send, and none loaded during the restore. At the start no company is loaded; the book is loaded by Tally's own Select Company screen, at step 1 and again after the restore. Another company loaded at the start: STOP-OTHER-COMPANY, shut nothing. The book absent from Select Company at step 1: STOP-BOOK-ABSENT. **The bind** is checked before anything is written: M1's state (`measure.py state M1`: one company row, the book's GUID, ALTMSTID 210, no ALTVCHID), then I1, G1 and U1 byte-equal to the pins (`measure.py bind`). Any miss is STOP-BOOK-STATE: nothing is written and nothing is restored. The write is R4's, once; the restore R5's, once.

R4. THE ELEVEN SENDS AND THE ONE WRITE (RR R4 and v3 C3, changed). Only `send.py` sends, and only the eleven requests it names, in its fixed order M1 I1 G1 U1 W M2 I2 M3 I3 G3 U3, one at a time, each once in the row's life whatever happened to it, to `http://127.0.0.1:9001` only, by v3 C3's curl line with `%{time_starttransfer} %{time_total}` added to its `-w` (as RR's), and no client timeout.
- **The reads.** The four read files are byte-identical copies of RR's (each sent to this book in Educational Mode by rows 1381-RA and 1381-RR, so none is a NEW SHAPE).
- **The write.** W's file is master's `stock-create-lab-plain-create.request.utf16le.xml`, byte-identical: row 1381-R1's b1, which created one stock item on this book, licensed. `send.py` holds its sha256 and bytes as well as `SHA256.txt`, and parses every request before it sends it: W's must be an import and every other an export, so nothing else can import. W is sent only after the bind is met (R1) and the precheck is met (R5), and is sent ONCE in the row's life: `send.py` writes a start marker before curl starts, so a W whose answer never came is never sent again, and nothing is sent after it.
- **v3 C3's "the MARKS answer read just before it".** For W that is M1. I1, G1 and U1 are read after it and the precheck reads files only; no key is pressed in Tally from M1 to W. This is a change from row 1381-R1, which sent a marks read straight before its write: here the bind needs I1, G1 and U1 first, and a second marks read would be a twelfth send.
- **After W**, before anything else: a screenshot of the whole Tally window (v3 C3, "after every write"); `send.py` will not send M2 without it. A dialog there: STOP-DIALOG (R7), and nothing further is sent.
- **Failures.** A non-zero curl exit, a status other than 200, a missing or different CONTENT-LENGTH, an empty answer, or an answer above 2,000,000 bytes is STOP-REQUEST-FAILED, recorded as "the request failed", never as "nothing found" and, for W, never as "nothing created"; `send.py` then refuses every later send. A request without an answer in 10 minutes is STOP-NO-ANSWER (v3 C3; row 1381-R1 used 15): that curl is left running and nothing is sent again; a screenshot of Tally's window may and should be taken while it waits.

R5. NO BACKUP; THE ONE RESTORE (v3 C5 dropped; v3 C6 kept in full; RR R5 changed).
- **No backup.** v3 C5's backup before the first change is not taken. The bind (R1) shows the book byte-equal to its state just after row 1381-RR's restore of BK-S (lab 1381-RR, 26 Nov 2026: M, I, G and U after that restore equal to these pins), so BK-S already is this row's backup; a backup in Educational Mode would be another act this lab has not measured.
- **The precheck**, RR's three checks and no others (the run coordinator's ruling, 26 Nov 2026), now before the write: with the book loaded, after the bind, `restore.py precheck` checks BK-S as `plan` does, the fallback (one file `TDBK1800_<company number>.001` in `C:\lab\1381-o\backup-1`, its recorded bytes and sha256, BK-S's company number) and that the company's data folder exists and can be listed. Any miss: STOP-RESTORE-SOURCE, and nothing is written. The write, not the shut, is this row's point of no return, so the precheck gates the write (`send.py W` needs `local/precheck.txt` and a `PRECHECK MET` record ending `exit 0`).
- **The restore** is made only after W is graded `WRITE ADMITTED` (R6), M2's state is met and the aim is `AIM SHOWN`: `restore.py plan` refuses unless `w-grade.txt` holds `WRITE ADMITTED` and `aim.txt` holds `AIM SHOWN`, each ending `exit 0`. After a write refused in-band there is nothing to undo. After any other outcome (a STOP at M2 or I2, `WRITE UNCLEAR`, `WRITE NOT PARSED`, a failed request) a restore is made only on the run coordinator's word and needs a new sheet, since this one's later reads (M3 to U3) cannot run after it (the run coordinator's ruling, 26 Nov 2026). The source, the plan (which needs the precheck, `WRITE ADMITTED` and `AIM SHOWN`), the shut, the keys, the two prompts, the after-record, the stops and the load are RR R5's exactly (lab 1381-RR, step 4: back at Select Company about 5 s after the Replace). After the load, before any request, a screenshot of the whole Tally window and one of the Gateway showing the book as the one company; then the reads, MARKS first (M3). The book must then hold BK-S's state (`measure.py state M3`); if it does not: STOP-RESTORED-STATE, and I3, G3 and U3 are not sent.
- **The fallback** is row 1381-O's backup-1 (the sheet's The backup), restored only on the run coordinator's word, never inside this row. It is itself a restore in Educational Mode of a different file, which no row has made: the way back after a failed BK-S restore is a route not yet proven.

R6. READING AN ANSWER (RR R6 and v3 C4, kept for the reads; changed for the write's answer). The reads as RR R6: `measure.py` decodes UTF-16LE with or without a byte-order mark; drops only the characters XML forbids, keeping 9, 10 and 13; parses as XML, never a text search on the bytes; reads rows only as children of `ENVELOPE/BODY/DATA/COLLECTION`; an answer whose send failed, that is empty, that does not parse, or that is not a success envelope is `NOT READ`, never zero rows; so is a pinned file that is missing or not its pin. **The write's answer** is graded by parsing (`measure.py write`), counters read only as children of its `RESPONSE`, each present once as a whole number written plainly, ASCII digits with no leading zero but `0` itself (an empty counter is not zero), and every counter's text and LINEERROR printed by `repr()`, so that no text of the answer can stand as a line of its own:
- `WRITE ADMITTED`: CREATED 1, ALTERED, DELETED, COMBINED, IGNORED, ERRORS, CANCELLED and EXCEPTIONS 0, no LINEERROR (v3 C4's EXPECT; row 1381-R1's answer, licensed). LASTVCHID and LASTMID are recorded.
- `WRITE REFUSED`, an in-band refusal: an error envelope (HEADER/STATUS not 1) holding no `RESPONSE` and no counter, or every counter present and CREATED, ALTERED, DELETED and COMBINED all 0. This answers Q1 "no" and is recorded whole, every LINEERROR with it; it is not a STOP. Changed from v3 C4's "anything else = STOP".
- `WRITE UNCLEAR`, anything else that parses (a change counter above 0 beside an error, CREATED above 1, a counter missing, repeated or not written plainly, an envelope with STATUS 1, an error envelope that also holds counters): STOP-WRITE-ANSWER, since the book may hold a change this row did not plan.
- `WRITE NOT PARSED`: W's send was `SENT-OK`, so Tally answered, but its answer is not UTF-16LE or does not parse: STOP-WRITE-ANSWER, as UNCLEAR, since the book may hold a change (the run coordinator's ruling, 26 Nov 2026). Only a send that failed or did not finish is `NOT READ` for W: STOP-REQUEST-FAILED, "the request failed", never "nothing created". For the reads, an answer that does not parse stays `NOT READ`: STOP-REQUEST-FAILED. v3 C4's "the counters are never the proof: the read after it is" is kept: M2 and I2 are that proof.

R10. AFTER A STOP (RR R10 and v3 C8, changed). A STOP leaves things as they stand: nothing further is sent, keyed or restored, no file is moved or deleted, no process is ended. One exception, v3 C8's: after STOP-WRITE-ANSWER (`WRITE UNCLEAR` or `WRITE NOT PARSED`: a write that answered, so not a request that failed), M2 and its state line are run once to record the mark; nothing else (`send.py` sends M2 after those two grades, and never I2). A STOP after an admitted W (STOP-AIM-STATE, or a failed request at M2 or I2) waits for the run coordinator's word, and so does any restore after it (the run coordinator's ruling, 26 Nov 2026). The report names the STOP, the files that show it and **what the book holds**, in these words:
- before `BIND MET` (steps 0 and 1 up to the bind line): "the book as found, its state not yet checked, unchanged";
- at the bind, STOP-BOOK-STATE: "the book as found, not at BK-S's state, unchanged";
- after `BIND MET`, before W is sent (step 2, and step 3 up to the send): "the book as found, at BK-S's state, unchanged";
- from W's send until its grade: "W sent; the book's state unknown";
- W graded `WRITE REFUSED`, with M2 at 210: "W refused in-band; the book as found"; with M2 not at 210: "W refused in-band, but the mark moved: the book's state unknown"; with M2 not read or its send failed: "W refused in-band; the mark not read: the book's state unknown";
- W graded `WRITE UNCLEAR` or `WRITE NOT PARSED`: "W sent; the book may hold a change; not restored";
- W's send failed (`NOT READ`) or no answer came (STOP-NO-ANSWER): "W sent; the request failed or never answered: the book's state unknown; not restored";
- W graded `WRITE ADMITTED`, until the restore's first key (steps 4 and 5 up to the Restore screen): "W admitted; the book changed by W, not restored";
- from the restore's first key to `restore.py after`: "a restore of BK-S begun; the book's data folder in an unknown state";
- after it, until M3, I3, G3 and U3 are all read: "BK-S restored; the book as the last reads show";
- all four byte-equal to the pins: "BK-S restored; the book at BK-S's state";
- any of them not: "BK-S restored but not equal to the pins". The way back is then the fallback, only on the run coordinator's word, and it is itself an unproven Educational-Mode restore of a different file.
The close (R11) follows a STOP only on the run coordinator's word, and so does any restore. **A book left changed or stuck blocks only the 1381 lab rows**: no other row uses `BRIDGE STOCK CREATE LAB`.
