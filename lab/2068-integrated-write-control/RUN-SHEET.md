# 2068 write control (#2068, Part of #692): the non-integrated stock company built again with inventory integrated with accounts, then `trial_balance` and the ledger collection read against Tally's own Trial Balance

Not for merge. About 2 hours. This sheet WRITES, on a NEW synthetic company, by hand on Tally's screens; ComplyEaze Bridge only reads. `SHA256.txt` lists every file here with its bytes; check it before step 0.

## What it decides
`lab/692-nonint-lab-answers` built `BRIDGE NONINT LAB` with "Integrate Accounts with Inventory" set to No and a ledger `Closing Stock` under Stock-in-Hand (opening 1,000.00 Dr, a closing balance of 1,400.00 Dr entered on the ledger's own screen). There the ledger collection and `trial_balance` kept the ledger's closing at its opening (-1,000.00) and showed the 400.00 only as a debit total; the Profit and Loss and Balance Sheet used 1,400.00 (#2068). Nobody has built the same book with integration ON. The earlier control sheet for it (`lab/2068-integrated-control`, not run) would have read `BRIDGE TIEOUT D`, which is integrated but holds no Stock-in-Hand ledger, so it could not show the ledger's behaviour. This sheet builds the like book: the same masters, the same two accounting vouchers, the same stock side, with integration left at Tally's default (Yes), and reads it the same ways. (The NONINT book was created with integration Yes and switched to No before any master was keyed, as its `RESULTS.md` says, so the two books are alike from K2 onwards.) Whatever Tally does when asked for the same book (it may refuse a ledger balance under Stock-in-Hand, or not offer a closing-balance field) is the result.

## What each part records
For this integrated book, set against the non-integrated one (`lab/692-nonint-lab-answers`, `RESULTS.md`):
- what Tally offered, refused or warned about at each of K1 to K6 (the stock ledger, its opening balance, a closing-balance field, the Stock Journal);
- Tally's Profit and Loss, Balance Sheet, Stock Summary and Trial Balance (both views);
- from the ledger collection (n-r3): the `Closing Stock` ledger's `TBALOPENING`, `TBALCLOSING`, `DEBITTOTALS`, `CREDITTOTALS`; from `trial_balance`: its row for the ledger (opening, debit, credit, closing), the `totals`, whether the closing totals tie, and for each row whether opening + debit + credit equals closing;
- whether the Balance Sheet export balances; whether the Stock Summary closing value equals the ledger's.
Either result is a record, not a pass. If K6a offers no Closing Balance field on this integrated book, the question whether the ledger's closing stays at its opening is not decided by this book, and the result says so. **Confidence:** one observation, PARTIAL until repeated.
