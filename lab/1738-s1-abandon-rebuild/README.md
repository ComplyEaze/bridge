# Lab run sheet: a statement build abandoned unsent, then rebuilt, sent and verified; what the other account's skip reads at each point (#1738, S1 evidence). SYNTHETIC COMPANY ONLY. Not for merge.

About 60 minutes. `LAB-COMMON.md` in this folder (v3, a byte copy from `lab/2015-goods-lines-notes`, sha256 `5370c6d288cd0f54a4ac547c513ec1648dd8bec0ea5a327d46b0de519a6369c6`) applies in full; where this sheet and it differ, the stricter holds. **WHAT IT DECIDES.** #1738's route S1 (an abandoned unsent statement build stops blocking the other account once another build of the same rows is found posted) is parked until live evidence answers the four checks its maintainer listed (#1738, comment of 21 Oct 2026). This sheet answers three with product tools only:
1. a build of a synthetic statement is abandoned unsent (built, never sent, never found posted);
2. the same file is built again, sent and verified (an unsent build holds no row: the rebuild refusal `import_txn_already_posted` covers only a row "another batch of this company already sent, or was found to have posted", `agent_import.rs` near the refusal);
3. what the other account's skip of the shared rows reads, (a) while only the abandoned build exists and (b) after the rebuild is posted and verified;
and the in-product half of the fourth: the same statement parsed twice, and over a wider window, gives the same row ids. Two downloads of one period from a bank are NOT measured (the statements here are made by a generator, once).

**PARSE ARGUMENTS.** Every parse: `statement_path`, `password_file`, `bank` `ubi` (the statements are Union Bank-shaped and print no totals: no `total_debits` or `total_credits`), `suspense_ledger` `TLab Suspense`, `from` and `to` as the step says (YYYYMMDD).
