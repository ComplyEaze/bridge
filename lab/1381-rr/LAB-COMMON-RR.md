# LAB-COMMON-RR: the rules row 1381-RR carries (written for this row, 26 Nov 2026)

This row makes one restore, of backup BK-S into the one synthetic book, in Educational Mode, and sends five reads by file around it. It keeps row 1381-RA's rules (`LAB-COMMON-RA.md`, lab/1381-ra-sheet at 30f5c820, R1 to R13) where they apply, and brings in LAB-COMMON v3's C6 (blob c4badf8c) for the restore, which RA's R5 dropped. Each clause says which RA clause, or which v3 clause, it keeps or changes. Where the run sheet and this text differ, the stricter holds. The lab's standing rules stand above both. Do not start the row without this text and v3 C6 in front of you.

R1. THE BOOK ONLY (RA R1, kept; its last sentence changed). The book is `BRIDGE STOCK CREATE LAB`, synthetic, with no other company loaded at any send, and none loaded during the restore. At the start no company is loaded; the book is loaded by Tally's own Select Company screen, at step 1 and again after the restore. Another company loaded at the start: STOP-OTHER-COMPANY, shut nothing. The book absent from Select Company at step 1: STOP-BOOK-ABSENT. The book's state is checked by M1 before anything else is done to it (`measure.py state M1`): anything but one company row, the book's GUID, ALTMSTID 210 and no ALTVCHID is STOP-BOOK-STATE, and nothing is restored. The restore is R5's, once.

R2. THE EDITION (RA R2, kept; one screen added). The lab's Tally runs in Educational Mode: its title band reads `TallyPrime EDU` (lab 2162-PA, 25 Nov 2026: the Silver Rental licence lapsed on 24-Nov-2026; lab 1381-RA, 25 Nov 2026, at all six screenshots). That is the state this row measures, not a STOP. A title band that does not read `EDU` at step 0, or that changes at any later screenshot, the screenshots after the restore included, is STOP-EDITION: nothing further is sent, and the row waits for the run coordinator's word.

R3. STEP 0 (RA R3, kept; the order made exact). Straight after the row folder is made, before the fetch, the copy, any process listing and anything sent, a screenshot of the whole Tally window (a dialog, a message box or a half-entered screen is STOP-DIALOG before anything is sent); `tasklist` for `tally.exe`, exactly one line, its PID recorded; `netstat -ano` with a LISTENING line on `:9001` with that PID and a LISTENING line for another port (else the command failed); GET `/status` on 9001, curl exit 0 and status 200; no `bridge_mcp.exe` running (else STOP-STRAY); `check_sheet.py --fresh`. Then the load (R1), a screenshot of the Gateway showing the book as the one company, and Tally's current date as the Gateway shows it. v3 C2 d's MARKS read is M1, the first of the row's five reads. Never "open application" on Tally; click the existing window.

R4. THE FIVE READS (RA R4, changed). Only `send.py` sends, and only the five reads it names, in its fixed order M1, M2, I, G, U, one at a time, each once in the row's life whatever happened to it, to `http://127.0.0.1:9001` only, by v3 C3's curl line with `%{time_starttransfer} %{time_total}` added to its `-w` (as RA's `send.py` did), and no client timeout. The four request files are byte-identical copies of RA's (marks, items, groups, units; RA's count request is not carried), each sent to this book in Educational Mode by row 1381-RA, so none is a NEW SHAPE. `send.py` checks each request's sha256 and size against `SHA256.txt`, sends M2 only after M1's state is met and `restore.py after` has recorded, and sends I only after M2's state is met. Between M1 and M2 nothing is sent to Tally (no GET `/status`, no file); the only acts on Tally are the shut, the restore and the load of R5 and R7, and the screenshots. A non-zero curl exit, a status other than 200, a missing or different CONTENT-LENGTH, an empty answer, or an answer above 2,000,000 bytes is STOP-REQUEST-FAILED, recorded as "the request failed", never as "nothing found"; `send.py` then refuses every later send. A request without an answer in 10 minutes is STOP-NO-ANSWER: that curl is left running and nothing is sent again.

R5. THE ONE RESTORE (v3 C6, kept in full; RA R5 replaced). No write and no backup. One restore, of BK-S, by v3 C6 exactly, made by the operator on Tally's screen, never by a request:
- **The source** is identified by all of: its folder `C:\bridge-lab\1108r3\backups\bks`, its one file `TDBK1800_<company number>.001`, its bytes and sha256 as row 1108-R3 recorded them (the sheet's The backup), and the date and time the Restore list shows for it, `19-Nov-26 (7:40 pm)` (lab 1108-R3, step 9). Any one differing, or the folder holding another file: STOP-RESTORE-SOURCE, press no key.
- **Before it**, after the shut, `restore.py plan` checks the file's sha256 and bytes and that its folder holds that one file only, and writes `restore-plan.txt` (folder, file, bytes, sha256, company number, Restore Data Path, the two prompts) and a listing of the company's own data folder (the folder named by its number under the Restore Data Path). **After it**, back at Select Company and before the load, `restore.py after` checks the source again, lists that folder again and prints the difference.
- **The two prompts** expected are the only ones answered: "Accept ?" = Yes, pressed only at a seen "Accept ?" (a screenshot first); "Company data folder (<number>) already exists ... Selecting Replace will overwrite the existing folder." = Replace, its number the book's. Any other prompt, an offer to repair, rewrite or migrate, or a list that differs from the plan: press no key, screenshot, STOP-DIALOG.
- **Any licence, activation, renewal or Educational-Mode dialog or screen** from the shut's end to the load's end (R7's pair after the shut excepted): press no key, copy its text, screenshot, STOP-LICENCE.
- **Not completing:** the Replace prompt not appearing, the restore not back at Select Company in 10 minutes, `restore.py after` finding the company's data folder absent, or the book missing from Select Company or not opening afterwards: press no key, screenshot, send nothing, STOP-RESTORE "the restore of BK-S did not complete".
- **After it**, the book loaded alone; before any request a screenshot of the whole Tally window (no dialog, no half-entered screen) and one of the Gateway showing the book as the one company; then the reads, MARKS first (M2). The book must then hold the state of R1 (`measure.py state M2`); if it does not: STOP-RESTORED-STATE, and I, G and U are not sent.
- **The fallback** is row 1381-O's backup-1 (the sheet's The backup), restored only on the run coordinator's word, never inside this row. A fallback restore would itself be a restore in Educational Mode, the thing this row tests: the way back is a route this row has not yet proven. So before the shut, with the book loaded and M1's state met, `restore.py precheck` checks BK-S as `plan` does, the fallback (one file `TDBK1800_<company number>.001` in `C:\lab\1381-o\backup-1`, its recorded bytes and sha256, BK-S's company number) and that the company's data folder exists and can be listed. Any miss: STOP-RESTORE-SOURCE, and nothing is shut or restored.

READING AN ANSWER (RA R6 and v3 C4, kept). `measure.py` decodes UTF-16LE with or without a byte-order mark; drops only the characters XML forbids, raw or as references, keeping 9, 10 and 13; parses as XML, never a text search on the bytes; reads rows only as children of `ENVELOPE/BODY/DATA/COLLECTION` (the CMPINFO block's bare count lines are not rows). The report names the STOP, the files that show it and **what the book holds**, in these words: before the restore began (steps 0 to 3), "the book as found, not restored"; from the restore's first key to `restore.py after` (step 4), "a restore of BK-S begun; the book's data folder in an unknown state"; after it (steps 5 to 7), "BK-S restored; the book as the last reads show". The close (R11) follows a STOP only on the run coordinator's word, and so does any restore (R5's fallback).
