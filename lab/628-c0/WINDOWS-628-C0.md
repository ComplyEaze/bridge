(26 Oct 2026; v1.2 replaces v1 and v1.1: the hand-written voucher read is gone, every voucher read is a call to the lab's ComplyEaze Bridge build, and a company without a GSTIN gets one from the owner instead of a STOP.) LAB-COMMON v3 applies in full; where an item and LAB-COMMON differ, the stricter holds.

Why: issue 628 asks for Purchase vouchers through ComplyEaze Bridge. No Purchase has ever been posted over the gateway in its shape, and the only Purchase bytes held were keyed on a book whose own GSTIN Tally may not accept (both read GSTR uncertain). This item is the first of a sequence (C0 keyed reference; C0b the copies issue 1904 needs; then C1 the same voucher imported in Bridge's shape, C3 references kept elsewhere, C4 a renamed Purchase type, C6 an out-of-state supplier), each written only after the previous one's answer. C0 answers one question first: on a company whose GSTIN is the gate's synthetic identifier, does a clean intra-state Purchase read as included (not uncertain) in Tally's GST status? If not, no later item can use that status as evidence, and that is recorded before anything else is built.

## The build, the relay and the calls
- Requests reach Tally only through ComplyEaze Bridge's own tools (AGENTS.md P7 and P8): the operator sends no hand-written request but the MARKS read below, GS1-L1's file unchanged.
- The build: the `bridge_mcp` program the lab config's line `bridge-lab-gs1` already runs (GS1-L1's build of pull request 1867; its sha256 as GS1-L1's go-ahead named; another hash = STOP). Posting and ledger creation stay OFF. Exactly ONE ComplyEaze Bridge is connected to the assistant, under that server name; every call goes to it with exactly the arguments the step gives, one call at a time; after every call the assistant keeps the answer whole as a file in the evidence folder (named by step), with its size and sha256. A call in flight is never cancelled, abandoned or repeated; nothing is keyed or sent while one runs.
- The relay: `lab/gs1-relay` at the commit GS1-L1 run-3 used (`e5dffc2b`), checked against its own SHA256.txt and self-tested as its README says, before step 6. A relayed call: start the relay with `--record C:\bridge-lab\628\relay\c0` (a new folder), set the `bridge-lab-gs1` line's Tally port to 9011 and restart that server; after the step, Ctrl+C the relay, set the port back to 9001 and restart the server. A request the relay refuses = the call fails = STOP, the folder kept. A direct call: the server on 9001, no relay.
