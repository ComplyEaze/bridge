# 2017 and 2018 stock by godown and by batch (#2017, #2018): Tally's own godown-wise and batch-wise stock reports, read by name from the screen's title, against the Stock Summary, on the synthetic book that holds two godowns and batches

Not for merge. About 90 minutes. READS ONLY: nothing is created, altered, imported or restored, and no backup is needed (C5 and C6 do not apply: the book does not change). `SHA256.txt` lists every file here with its bytes; check it before step 0.

## What it decides
`stock_summary` returns closing stock per item for the whole company. #2017 (closing stock by godown) and #2018 (closing stock by batch, and expiry) both wait on one capture each: Tally's own report, requested by name, with its element names and amounts compared with the Stock Summary for the same period. The report's name over the gateway is not known, and a screen's title is not always the gateway's ID (the screen "Profit & Loss A/c" is the ID "Profit and Loss"). A report ID that Tally does not know is, in the repo's measurements, refused in band (STATUS 0 and a line error saying the report was not found) and the GST report-name sitting (`lab/2011-gst-report-names-answers`, 7.2) saw the same, one name answering a 200 with no bytes; a modal "Error in TDL" dialog is the failure of an unknown Collection ID, not of a report ID, but this sheet still stops on any dialog. So each report's candidate names come only from the title Tally's own screen shows for it, as a short closed list sent once each in the Stock Summary's own request shape with only the ID changed, with one deliberately unknown name as a control for what a refusal looks like.

Captured already: the godown masters (`masters` kind `godowns`), the godown names on invoice goods lines (`GODOWNNAME`), the batch rows of invoice vouchers, the company's batch flag. Not captured: any closing stock by godown or by batch, a batch master, an expiry or manufacturing date.

Differences from LAB-COMMON, the stricter rule holding everywhere else:
1. **Two kinds of read.** Tool reads are calls of ComplyEaze Bridge's built tool, one at a time. Raw reads by curl are allowed by the owner's decision of 26 Oct 2026 for shape discovery: each is the committed Stock Summary report request (`templates/stock_summary_request.utf16le.xml`, the fixture `stock_summary_report_fy_request`) with only the report ID, the company and the dates changed, written by `make_report_request.py`, used as an instrument and sent once as C3 sets out. No other request is sent.
2. **No ID is guessed.** A candidate ID is derived only from the title Tally's own screen shows for that report, copied exactly (step 3), by these rules and no others: (1) the title as shown; (2) the title with `&` written `and` and every `/` dropped; (3) the title with its spaces removed. A candidate is sent only if it is plain (letters, digits, spaces, hyphens), once, in that order, and the first one that answers with data ends that report's list. One more request, the control, uses the name `Bridge Probe Unknown` (no such report exists): it shows what a refusal looks like. 3. **Marks.** `tally_status` carries no marks. M (`ALTMSTID`) and V (`ALTVCHID`) are read with `ledger_masters` (basic, first page, no `snapshot_id`): `snapshot.master_alter_id`, `snapshot.voucher_alter_id`, `snapshot.reused` false. Marks are read before and after the group of raw reads, and must be equal.
4. **One Tally.** At step 0 and at the end, as C2 a and b set out (the process list and the listener on port 9001) plus `Get-NetTCPConnection -LocalPort 9001 -State Listen`: exactly one `tally.exe`, and it owns port 9001. A screen-control tool brings no window forward.
5. **Keys.** The screens opened are reports, their menus and the Gateway only. In a menu use arrows, Enter and Escape only (letters typed at the Gateway act as menu keys). In a report use arrows, Enter on a godown, item or batch line to open its drill-down (never deeper than the item or month level, and never Enter on a voucher line: a voucher opens an alteration screen, which is left only by ONE Ctrl+Q after a screenshot shows its title, never Escape, C7), and F2 to set the report's period. Leave a report with one Escape per level (C7 allows Escape on reports), a screenshot after each; **never Ctrl+Q or Escape at the Gateway of Tally**. No entry or alteration screen is opened on purpose.
6. **A modal dialog** at any step (an "Error in TDL" message above all): screenshot it, copy its text exactly, press NO key, send NO request, and report (C7). It stays on the screen until the run coordinator answers; the gateway is blocked meanwhile. A 0-byte 200 answer, an empty envelope and an in-band refusal (STATUS 0 with a line error) are **results** for these sends, not STOPs: C3's "empty body" STOP is set aside for them and nothing else.
